# Complete Purge of Restaurant Legacy Layer in Favor of Pure Retail Store Architecture

Following the cloning of the Bokrah Restaurant codebase into Bokrah Retail, residual restaurant shim exports (`lib/app/features/restaurant/`), dual-mode `isRestaurant` conditionals, unused meal graphics (`assets/images/`), legacy `/restaurant/*` routes, and outdated `/api/restaurants` endpoint bindings remained as technical debt. We decided to execute a clean break: completely deleting the legacy restaurant shim folder and unused assets, removing compatibility aliases/subclasses from `Store*` domain models, decommissioning `/restaurant/*` routes, and standardizing authentication and backend contracts strictly on retail stores (`POST /api/stores`, role `store`). Maintaining parallel compatibility shims increased maintenance overhead, caused confusing dual terminology, and increased deployment bundle size without serving any production retail client.
